# Идея

Мои дотфайлы лежат в [отдельном Git-репозитории](https://github.com/laserattack/dotfiles).
Конкретные настройки здесь разбирать не буду: интереснее сама схема
хранения и развёртывания окружения.

Оригиналы файлов находятся в репозитории, а на привычных для программ
местах в домашнем каталоге создаются символические ссылки на них.
Получается одна рабочая версия каждого файла: редактор и приложение
обращаются к нему через ссылку, а изменения видны в `git diff`.

```text
~/projects/dotfiles/      ← оригиналы под управлением Git
├── deploy.sh             ← скрипт развёртывания
├── MANIFEST              ← список действий
└── …                     ← файлы и каталоги с настройками

~/…                       ← ссылки на файлы и каталоги репозитория
```

Содержимое репозитория само по себе не означает, что файл будет
развёрнут. За это отвечает отдельный манифест. Можно хранить рядом
вспомогательные материалы и включать в развёртывание только нужное.

# Манифест

`MANIFEST` — обычный текстовый файл. Каждая запись имеет формат:

```text
относительный_путь|операция|каталог_назначения
```

Сейчас скрипт поддерживает одну операцию — `symlink`.
Первое поле задаёт путь относительно корня репозитория. Третье —
дополнительный каталог относительно домашней папки; оно может быть пустым.

Пример на условных именах, без перечисления моих конфигов:

```text
.example|symlink|
.config/example|symlink|
helper|symlink|.local/bin
#disabled|symlink|
```

Такой манифест задаёт следующие соответствия:

| В репозитории | Ссылка в домашнем каталоге |
| --- | --- |
| `.example` | `~/.example` |
| `.config/example` | `~/.config/example` |
| `helper` | `~/.local/bin/helper` |

То есть третье поле — именно префикс каталога назначения. Имя из
первого поля дописывается к нему целиком. Отдельного поля для
переименования файла нет.

Пустые строки можно использовать для разделения записей на группы.
Для отключения записи ставлю `#` непосредственно перед ней, без пробела:
`#disabled|symlink|`. Почему это существенно — ниже, в разборе парсера.

# Скрипт целиком

Ниже моя текущая локальная версия
[`deploy.sh`](https://github.com/laserattack/dotfiles/blob/main/deploy.sh).
Она ничего не копирует: создаёт каталоги назначения и символические ссылки.

```bash
#!/usr/bin/env bash

set -e

SCRIPT_DIR="$( cd "$( dirname "$BASH_SOURCE[0]" )" && pwd )"

symlinkFile() {
    filename="$SCRIPT_DIR/$1"

    if [ -z "$2" ]; then
        destination="$HOME/$1"
    else
        destination="$HOME/$2/$1"
    fi

    mkdir -p $(dirname "$destination")

    if [ -L "$destination" ]; then
        echo "[WARNING] $filename already symlinked"
        return
    fi

    if [ -e "$destination" ]; then
        echo "[ERROR] $destination exists but it's not a symlink." \
             "Please fix that manually"
        exit 1
    fi

    ln -s "$filename" "$destination"
    echo "[OK] $filename -> $destination"
}

deployManifest() {
    for row in $(cat $SCRIPT_DIR/$1); do
        # you can write one-line comments in MANIFEST
        # like Python comments
        if [[ "$row" =~ ^#.* ]]; then
            continue
        fi

        filename=$(echo $row | cut -d \| -f 1)
        operation=$(echo $row | cut -d \| -f 2)
        destination=$(echo $row | cut -d \| -f 3)

        case $operation in
            symlink)
                symlinkFile $filename $destination
                ;;

            *)
                echo "[WARNING] Unknown operation $operation. Skipping..."
                ;;
        esac
    done
}

if [ -z "$@" ]; then
    echo "Usage: $0 <MANIFEST>"
    exit 1
fi

deployManifest $1
```

## Как он работает

`SCRIPT_DIR` вычисляется по расположению самого скрипта, а не по
текущей директории терминала. Поэтому источники ссылок всегда ищутся
рядом с `deploy.sh`. При этом аргумент манифеста тоже подставляется
относительно этой папки: обычный вызов — `deploy.sh MANIFEST`.

Функция `deployManifest` разбирает записи на три поля по разделителю
`|` и выбирает действие через `case`. Неизвестная операция выдаёт
предупреждение и пропускается.

Функция `symlinkFile` собирает два абсолютных пути:

```text
источник:   SCRIPT_DIR / имя_из_манифеста
назначение: HOME / [каталог_назначения /] имя_из_манифеста
```

Затем создаёт родительский каталог и проверяет назначение:

- Если там уже символическая ссылка, печатает предупреждение и пропускает её.
- Если существует обычный файл или каталог, сообщает о конфликте и завершает скрипт.
- Если путь свободен, создаёт ссылку через `ln -s`.

Для каталога создаётся ссылка на каталог целиком, а не слияние его
содержимого с существующим каталогом назначения.

## Особенности этой реализации

Существующая ссылка считается достаточным основанием пропустить путь.
Скрипт не проверяет, куда она ведёт: даже ссылка на другой репозиторий
или оборванная ссылка попадёт в эту ветку. Поэтому предупреждение
`already symlinked` не гарантирует правильность назначения.

Ссылки абсолютные. Это удобно для однозначного пути к источнику,
но после перемещения репозитория старые ссылки нужно исправить.
Повторный запуск сам этого не сделает, поскольку существующие ссылки
пропускаются.

Парсер использует `for row in $(cat ...)`: он разделяет ввод по
пробельным символам, а не читает файл построчно. Поэтому в моём
формате нельзя рассчитывать на пути с пробелами или комментарии
из нескольких слов. Запись `#disabled|symlink|` пропускается целиком,
а слова после `# комментарий с пробелами` будут обработаны отдельно.
Вызовы внутри скрипта также не везде заключены в кавычки.

Наличие исходного файла отдельно не проверяется. `ln -s` может создать
ссылку на отсутствующий путь, так что успешное создание ссылки ещё
не доказывает, что её цель существует.

`set -e` останавливает выполнение при необработанной ошибке, но не
откатывает уже созданные ссылки. Если скрипт остановился на конфликте,
предыдущие записи манифеста могли уже примениться.

Эта схема позволяет держать оригиналы настроек в одном месте,
видеть историю изменений в Git и явно выбирать в манифесте, что
разворачивать в домашний каталог.

# Развёртывание на новой машине

```sh
git clone https://github.com/laserattack/dotfiles.git ~/projects/dotfiles
cd ~/projects/dotfiles
bash ./deploy.sh MANIFEST
```

Команды запускаются от обычного пользователя: именно его домашний
каталог должен получить ссылки.

После развёртывания работаю с файлами как обычно. Изменения проверяю
в репозитории:

```sh
cd ~/projects/dotfiles
git status
git diff
```

На другой машине можно получить изменения через `git pull`: поскольку
ссылки ведут на файлы рабочей копии, обновлённое содержимое доступно
по тем же путям.

Если добавилась новая запись в манифесте, запускаю развёртывание ещё
раз. Но удаление записи не удаляет старую ссылку из домашнего каталога:
обратной синхронизации у скрипта нет.
