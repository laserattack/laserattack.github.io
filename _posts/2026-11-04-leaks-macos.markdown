В [посте про утечки и производительность]({% post_url 2026-08-17-performance-leaks %})
я уже показывал проверку через Valgrind:

```sh
valgrind --leak-check=full --show-leak-kinds=all ./mado
```

В macOS для похожей проверки можно использовать системную утилиту `leaks`:

```sh
MallocStackLogging=YES leaks --atExit -- ./mado
```

Она запускает программу и проверяет утечки перед её завершением.
Аргументы программы можно дописать после `./mado`, например:

```sh
MallocStackLogging=YES leaks --atExit -- ./mado ls 's ~ ope'
```

Что здесь происходит:

- `MallocStackLogging=YES` включает запись стеков выделения памяти,
  чтобы в отчёте было видно, откуда пришла утечка. Переменная задаётся
  только для этого запуска и наследуется проверяемой программой.
- `--atExit` включает проверку при обычном завершении программы.
- `--` отделяет параметры `leaks` от команды, которую нужно запустить.

Для более полезных стеков стоит собрать программу с отладочной
информацией (`-g`). Оптимизация может усложнить сопоставление отчёта
с исходным кодом.

В отчёте нужно смотреть на количество утечек и их общий размер.
Если утечки найдены, ниже будут сведения о потерянных блоках памяти
и, при включённом логировании, стеки их выделения.

Это аналог Valgrind именно для задачи поиска утечек, а не полная замена
его Memcheck. `leaks` ищет выделенные блоки, до которых больше нельзя
добраться по указателям. Память, на которую ещё есть ссылки, считается
используемой, даже если программа фактически в ней уже не нуждается.

Подробнее: `man leaks` и
[документация Apple про поиск утечек](https://developer.apple.com/library/archive/documentation/Performance/Conceptual/ManagingMemory/Articles/FindingLeaks.html).
